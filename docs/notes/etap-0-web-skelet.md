# Этап 0 — скелет фронта: что сделал и почему

Задача 0.10, 24.09.2026. Задачу выполнял агент; решения по спорным местам — ниже.

## Что появилось

`apps/web` на Vite 8, React 19, TanStack Router и TanStack Query, MUI 9. Одна страница: заголовок и плашка статуса API, которая спрашивает `/api/health`. Три теста компонента на Vitest, Testing Library и MSW.

Версии зафиксированы точно: `react` 19.3.0, `vite` 8.3.0, `@tanstack/react-router` 1.170.39, `@tanstack/router-plugin` 1.168.40, `@tanstack/react-query` 5.103.2, `@mui/material` 9.4.0, `zod` 4.6.5, `vitest` 5.0.1, `msw` 2.15.0, `jsdom` 30.1.1.

Попутно: API переехал под префикс `/api`; корневой `pnpm dev` запускает API и фронт вместе; README дополнен шагом «Приложение», портами и командами.

## Решения

**API под префиксом `/api`, без исключений.** `app.setGlobalPrefix('api')`: маршруты стали `/api/health` и `/api/ready`. Основание — PRD, где cookie с refresh-токеном описана с `Path=/api/auth`. Проверки живости и готовности тоже под `/api`: тогда и прокси разработки, и nginx различают фронт и API одним правилом по началу пути, без переписывания адресов.

**Прокси разработки вместо CORS.** В разработке фронт на `:5173`, API на `:3000`. Vite пересылает всё, что начинается с `/api`, на Nest, и для браузера это один адрес — CORS настраивать не нужно. В production ту же роль сыграет nginx.

**Маршруты из файлов, сгенерированное дерево в репозитории.** Плагин роутера читает `src/routes` и пишет `src/routeTree.gen.ts` с типами всех маршрутов. Файл коммитится: `tsc --noEmit` плагин не запускает, и без файла проверка типов на чистом клоне и в CI упала бы. Из ESLint и Prettier файл исключён — его пишет машина.

**`queryClient` в контексте роутера.** Пока не используется. На этапе 1 маршруты смогут предзагружать данные в `loader` до рендера страницы.

**Ответ сервера проверяется zod-схемой.** Если контракт `/api/health` разъедется, ошибка возникнет в месте запроса, а не в разметке. Тест на это есть отдельно.

**Временный ручной клиент.** По `CLAUDE.md` клиент API генерируется из OpenAPI, но генерация — задача 1.7. До неё генерировать не из чего, поэтому `src/api/health.ts` — одна функция руками. Удаляется на задаче 1.7.

**Тема.** Одна светлая тема MUI (PRD §7) с локалью `ruRU`: встроенные тексты компонентов — пагинация, подписи таблиц — сразу по-русски.

**Тесты.** MSW перехватывает `fetch` и отвечает вместо сервера. Запрос без обработчика — ошибка теста (`onUnhandledRequest: 'error'`): тест не уйдёт в настоящую сеть незаметно. У каждого теста свой `QueryClient` без повторов — иначе ошибка показалась бы только после трёх попыток. Три случая: API работает, API отвечает 503, ответ не совпал со схемой.

## Грабли

- **Префикс тихо ломал фильтр логов.** Логгер исключал из автологирования `req.url === '/health'`; после префикса путь стал `/api/health`, и проверки живости полезли бы в лог. Исправлено вместе с префиксом — любое переименование пути надо проверять поиском по коду, а не только по маршрутам.
- **MSW хочет выполнить установочный скрипт.** pnpm 11+ без явного решения обрывает установку. Скрипт копирует файл воркера для моков в браузере — мы используем только режим для Node, поэтому `allowBuilds: { msw: false }`: скрипт рассмотрен и запрещён, решение лежит в репозитории.
- **Слишком свежая версия.** С pnpm 11 по умолчанию действует `minimumReleaseAge` = 1440 минут: версии моложе суток не ставятся — защита от захваченных пакетов, которые обычно снимают с публикации в первые часы. Агент выбирал версии в своей среде на pnpm 10, где этой проверки нет, и взял `@tanstack/react-router@1.170.39`, опубликованный за 20 часов до установки. В `pnpm-workspace.yaml` появилось исключение `minimumReleaseAgeExclude` для этой версии. После 13:37 UTC 24.09 версия старше суток, и исключение можно удалить. Правило для агента: брать версии старше суток.
- **`pnpm dev` гасит всё сразу.** API и фронт идут одной командой в одной группе процессов, и Ctrl+C останавливает оба. Остановить один — запускать их в двух терминалах: `pnpm --filter @jdm/api dev` и `pnpm --filter @jdm/web dev`.
- **404 на `/favicon.ico` в консоли.** Браузер сам запрашивает иконку. Пустая иконка в `index.html` (`<link rel="icon" href="data:," />`) убирает шум — чистая консоль нужна, чтобы замечать настоящие ошибки.

## Проверено

В среде агента до записи в репозиторий: `tsc`, три теста, `eslint`, `prettier`, `vite build`, затем API и фронт запущены вместе, запрос через прокси `:5173/api/health` отвечает, страница открыта в Chromium — плашка «API работает», в консоли браузера ошибок нет. Коммит `8e62cc0`.
