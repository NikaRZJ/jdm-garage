# Этап 0 — CLAUDE.md и скиллы: что сделал и почему

Задача 0.12, 25–26.09.2026. Делали вместе: тексты писал агент, решения по границам и правилам принимал разработчик, проверку в Claude Code делал разработчик.

## Что появилось

`CLAUDE.md` доведён от черновика 14.09 до рабочего файла: ссылки на PRD, контекст и план задач; команды разделены на «есть сейчас» и «появятся на этапе 1»; раздел «Скиллы»; правила 9–11 — уроки этапа 0. Три скилла в `.claude/skills/`: `/adr` — записать решение по шаблону, `/tests-by-layer` — какие тесты писать и как, `/finish-task` — закрыть задачу: проверки как в CI, заметка, тексты коммита и PR. В `.gitignore` — `.claude/settings.local.json`, файл локальных разрешений Claude Code.

## Решения

**Набор скиллов.** В PRD §5.7 был «чек-лист pull request'а» — расширен до `/finish-task`, потому что PR — последний шаг закрытия задачи, а перед ним проверки, тесты, безопасность, ADR и заметка; чек-лист сам по себе не гарантирует, что остальное сделано. Был «создание миграции по описанию» — снят: генерация миграций спорит с правилом «руками». Вместо него к задаче 1.2 появится скилл ревью миграции по чек-листу. PRD 0.6.

**Уроки этапа 0 — в правила, а не в заметки.** Заметки агент не читает, `CLAUDE.md` читает всегда. Четыре урока стали правилами: секреты не печатать, `docker compose config` только с `--quiet` (сессия 4); незнакомый термин сначала объяснить, потом спрашивать (сессия 7); настройки образа — из образа, поведение библиотеки — из исходника (сессии 4 и 7); версии пакетов старше суток (сессия 8).

**Границы правила «руками».** При проверке Claude Code сам назвал четыре места, где правило не прописано. Решения разработчика: auth — ядро на `jose` (выдача, ротация, отзыв, семьи токенов, проверка access) пишет разработчик, обвязку — агент; фильтры каталога — CRUD-список, делает агент, SQL ревьюит разработчик, индексы и поиск — разработчик; на этапе 3 `Dockerfile` и prod-Compose пишет разработчик, скрипты бэкапа — агент, восстановление проверяет разработчик; сливает PR только разработчик, авто-слияние не включается.

**«Пока не попросят прямо» переписано.** Claude Code заметил двусмысленность: «напиши миграцию» можно прочитать как прямую просьбу. Теперь правило отменяется только явно, для конкретного случая: «в этот раз миграцию пишешь ты».

**Коммит, push и PR — после «да».** Агент показывает команды и тексты, разработчик подтверждает. Так решения о том, что уходит на GitHub, остаются за человеком.

## Проверено

Prettier по всем новым файлам зелёный; шапки скиллов разбираются как YAML, имена совпадают с папками. Проверка в приложении Claude, вкладка Code, папка репозитория, режим Manual:

- в меню `/` видны `adr`, `tests-by-layer`, `finish-task`;
- на вопрос «что ты делаешь сам, а что оставляешь мне» ответ совпал с `CLAUDE.md` и заметкой об уроках, плюс список непрописанных границ;
- на «напиши миграцию для таблицы listings» — отказ со ссылкой на правило «руками» и задачу 1.2, без единой строки SQL.

Попутно Claude Code нашёл два противоречия в PRD §6.2–6.3, которые решаются перед задачей 1.2: `created_by` ссылается на `users`, а таблица пользователей появляется только на этапе 2; переход `draft → archived` разрешён, но `CHECK` публикации допускает пустые поля только у `draft`, и неполный черновик в архив не пройдёт. Колонки `embedding*` и `price_jpy` из таблицы §6.2 относятся к этапам 4 и 5, в 1.2 не переносятся.

## Грабли

- **Файлы для агента проверяются только агентом.** `CLAUDE.md` и `.claude/skills/` читает Claude Code; сессия Cowork их не подхватывает. Поэтому приёмка — запуск в Claude Code и вопросы, а не чтение файла глазами.
- **Скилл с побочными действиями подключается сам.** `/finish-task` срабатывает на «готово» и «закрываем». Это удобно, но перед коммитом у него жёсткая остановка; если понадобится только ручной вызов — `disable-model-invocation: true` в шапке.
