# ADR-004. RustFS против Garage, MinIO и облачного S3

- Статус: принято
- Дата: 19.09.2026
- Решение обсуждено с разработчиком, текст записан агентом по итогам обсуждения

## Контекст

В проекте есть фотографии машин: до 20 снимков на карточку, превью трёх размеров, загрузка через API из админки. PRD §5.3 требует S3-совместимого хранилища, а не локального диска: работа с объектным хранилищем — одна из учебных целей, и она же снимает привязку к файловой системе конкретного сервера перед этапом 3.

Изначально в PRD стоял MinIO — очевидный выбор для локального S3. К сентябрю 2026 он выбыл: community-образы Docker и бинарники не публикуются с октября 2025, в декабре 2025 проект переведён в режим поддержки, в апреле 2026 репозиторий архивирован. Ставить сервис без обновлений безопасности в контур, который пойдёт в production, нельзя.

Важное свойство задачи: S3 — это протокол, а не продукт. Приложение работает через `@aws-sdk/client-s3` и знает только адрес, ключи и имя bucket. Поэтому выбор реализации обратим: смена хранилища — правка `compose.yaml` и `.env`, а не правка кода. Необратим только перенос уже загруженных файлов.

## Варианты

**Локальный диск.** Проще всего и без лишнего контейнера. Отклонён: не даёт учебной цели, привязывает к файловой системе одного сервера, усложняет бэкап и переезд.

**MinIO.** Отклонён по причинам выше: образы не публикуются, репозиторий архивирован.

**Garage** (v2.4.x, Rust, один бинарник). Зрелее RustFS, проверен в эксплуатации, S3 API совместим с AWS SDK v3. Два минуса: лицензия AGPL-3.0 и отсутствие встроенной веб-консоли — bucket и ключи создаются через CLI внутри контейнера. AGPL при самостоятельном размещении без модификации и распространения последствий не создаёт, но требует внимания, если проект перестанет быть учебным.

**SeaweedFS** (Apache-2.0). Ближайший «drop-in» для MinIO по возможностям, но тяжелее по конфигурации: несколько компонентов вместо одного сервиса. Для одного сервиса с фотографиями — лишняя сложность.

**Облачное S3** (Yandex Object Storage, Selectel). Снимает эксплуатацию полностью и в перспективе правильный вариант. Отклонён на этапе 0 по двум причинам: локальная разработка и тесты требуют, чтобы контур поднимался одной командой без внешних учётных данных, и учебная цель — поднять хранилище самому. Остаётся запасным вариантом в §5.4, когда объём фотографий вырастет.

**RustFS** (Apache-2.0, Rust, один контейнер). Веб-консоль на отдельном порту, MinIO-совместимые имена переменных, S3 API. Минус — зрелость: `1.0.0` вышла 16.09.2026, за три дня до этого решения; до конца июля 2026 проект был в бете. Документация на момент внедрения противоречит сама себе.

## Решение

RustFS `1.0.0` — сервис `storage` в `compose.yaml`: порты `9000` (S3 API) и `9001` (веб-консоль), оба привязаны к `127.0.0.1`; именованные тома на `/data` и `/logs`; ключи доступа из `.env` через обязательную форму `${VAR:?}`; bucket `photos`.

Причины именно RustFS против Garage: лицензия Apache-2.0 вместо AGPL и веб-консоль, которая на этапах 0–2 экономит время на создании bucket и разборе проблем. Против незрелости играет обратимость: код приложения от реализации хранилища не зависит.

Локальный диск, MinIO и SeaweedFS отклонены. Облачное S3 — путь отхода, а не альтернатива на этапе 0.

## Последствия

Хорошее: контур поднимается одной командой без внешних учётных данных; один и тот же образ в dev и production, то есть интеграционные тесты файлового модуля идут против настоящей реализации, а не против заглушки; навык работы с объектным хранилищем получен; лицензия вопросов не ставит.

Плохое, с которым придётся жить:

- **Версия 1.0 возрастом в дни.** Возможны расхождения в мелочах S3 API. Проверяется на этапе 2 интеграционными тестами файлового модуля — загрузка, подписанные URL, path-style адресация — против образа `rustfs/rustfs:1.0.0`.
- **Документация не источник правды.** Порты и имена переменных выяснялись через `docker image inspect` и `--help`; расхождения записаны в `docs/notes/etap-0-infra.md`. Любую конфигурацию RustFS проверять через образ.
- **Тихий откат на публичные ключи.** Без заданных ключей сервис поднимается на встроенных `rustfsadmin`/`rustfsadmin`, сообщая об этом только предупреждением в лог. Обязательная форма `${VAR:?}` в Compose закрывает случай незаданной переменной; критерий приёмки — отсутствие предупреждений в логах и отказ входа под `rustfsadmin`.
- **Секреты в переменных окружения** видны в `docker inspect` и в списке процессов. На этапе 3 перейти на `RUSTFS_ACCESS_KEY_FILE` / `RUSTFS_SECRET_KEY_FILE`.
- **CORS консоли.** В образ зашито `RUSTFS_CONSOLE_CORS_ALLOWED_ORIGINS=*`. В production консоль наружу не публикуется вообще; пункт чек-листа PRD §8.
- **Перенос данных при смене хранилища** сейчас бесплатен, после наполнения фотографиями — нет. Пересматривать решение, если понадобится, до этапа 2.
