# ADR — запись архитектурного решения

Решение с альтернативами фиксируется в `docs/adr/NNN-slug.md`. Решает разработчик — в обсуждении, это и есть учебный момент. Агент пишет текст по итогам, разработчик читает и правит.

## Когда ADR нужен

- Выбор между двумя и более реальными вариантами с разными последствиями: библиотека, способ хранения, протокол, схема auth.
- Решение дорого отменить позже.
- Не нужен: настройка, которая меняется одной галкой; выбор, который прямо следует из PRD или уже принятого ADR.

Если решение принимают без ADR — напомни.

## Порядок

1. Убедись, что решение принято: в обсуждении прозвучал выбор разработчика. Если нет — перечисли варианты с последствиями и спроси. Не выбирай сам.
2. Номер. За темами закреплены: 001 монорепозиторий, 002 ORM, 003 auth, 004 хранилище объектов, 005 поиск — файлы 003 и 005 ещё не написаны, но номера заняты. Любое другое решение — следующий номер после 005; проверь `ls docs/adr`, чтобы не повторить существующий.
3. Имя файла — `NNN-slug.md`, slug по-английски через дефис: `002-orm.md`.
4. Текст — по шаблону ниже, по-русски. Образец — `docs/adr/002-orm.md`.
5. Если решение меняет правила для агента — поправь `CLAUDE.md` в том же PR.

## Шаблон

```markdown
# ADR-NNN. <Выбранный вариант> против <альтернатив>

- Статус: принято
- Дата: ДД.ММ.ГГГГ
- Решение обсуждено с разработчиком, текст записан агентом по итогам обсуждения

## Контекст

Какую задачу решаем и в каких условиях: стек, учебная цель, бюджет времени, требования PRD. Без решения — только условия.

## Варианты

**Вариант А.** Что это, чем хорош, чего стоит. Почему принят или отклонён — по главному критерию.

**Вариант Б.** ...

## Решение

Что выбрали и главная причина — один-два абзаца. Конкретика: версии, настройки. Точка пересмотра — при каком условии возвращаемся к решению.

## Последствия

Хорошее: что становится проще.

Плохое, с которым придётся жить:

- **Коротко о цене.** Чем платим и как смягчаем.
```

## Правила текста

- В контексте — на что опираемся: раздел PRD, номер задачи, предыдущие ADR.
- Варианты описываются честно, включая сильные стороны отклонённых.
- Главный критерий для проекта — учебная цель, затем время: около 4 часов в неделю.
- Никаких «лучший» и «современный» без причины: у каждого утверждения — последствие для проекта.
- Отменённое решение не удаляется: статус меняется на «заменено ADR-NNN», новое решение — новым файлом.
